# FinMate Essential Rules

These are non-negotiable implementation constraints. If a proposed feature conflicts with one, stop and redesign the feature.

1. The LLM cannot independently approve or reject a loan or financing request.
2. XGBoost produces a risk/eligibility signal only; it is not the final governed decision.
3. Policy decisions must be deterministic, versioned, auditable, and reproducible for the same inputs.
4. SHAP explanations must be generated from the actual model version and feature payload that produced the displayed score.
5. Goal Recovery must use legitimate, governed alternatives. It cannot invent offers, override policy, or promise outcomes.
6. High-impact, exceptional, conflicting, or ambiguous cases must be capable of escalation to a human reviewer.
7. Never claim a real Paytm, bank, CRM, lender, or other external integration unless it is actually implemented and verifiable.
8. Never fabricate model performance, approval rates, business outcomes, scores, policy results, or customer outcomes.
9. Never use personal/private financial data in this prototype. Demo context must be simulated or explicitly approved for the project.
10. Keep LLM, workflow, CRM, bank, and other external integrations behind replaceable provider interfaces.
11. Do not modify raw datasets. Create derived artifacts only through documented, reproducible processes.
12. Preserve reproducibility of ML experiments: pin data version/reference, feature schema, split strategy, preprocessing, model parameters, random seed, metrics, and model artifact version.
13. Do not expose model internals or policy bypasses to the frontend or agent. Use validated backend APIs.
14. Store decision evidence separately: context snapshot, normalized features, model version/output, SHAP output, policy version/result, recovery rule version/options, and human action where applicable.
15. Treat text generated by the agent as an explanation of governed output, not as authoritative financial advice or a decision source.
16. Label all simulated data, integrations, pathways, and outcomes clearly in the demo.

## Implementation gate

Before merging any journey, scoring, policy, recovery, or integration feature, verify:

- Is the final outcome produced by deterministic policy rather than the LLM?
- Can the result be reconstructed from persisted versioned evidence?
- Does every displayed explanation match the underlying governed result?
- Is every external dependency replaceable and correctly labeled?
- Does the change avoid raw-dataset modification and private financial data?

If any answer is no, the implementation is not ready.
